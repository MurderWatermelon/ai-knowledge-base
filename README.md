# 个人 AI 知识库：中文语义检索与阅读理解

基于 Streamlit 实现文档解析、分块、中文语义检索、可选 Ollama 阅读理解，以及证据召回评测。网页与评测共用 `rag.py` 中的检索器，检索评测不调用大语言模型。

## 快速运行

推荐 Python 3.11 / 3.12。在项目目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

左侧默认使用“中文语义理解”，通过 Sentence Transformers 加载 `BAAI/bge-small-zh-v1.5`。它按含义查找相关段落，问题编码时加入该模型的中文检索指令，文档不加指令。首次需要联网下载约 100 MB 模型到项目的 `.model-cache/`，之后在本机计算向量。

若不想下载模型，可以切换“字符 TF-IDF（离线基线）”，依赖安装后这条检索流程不需要模型下载、API 密钥或 Ollama。两种方式的报告都会标明所用模型，不能将字符基线成绩当作语义模型成绩。

生成回答需要另外安装、启动 Ollama 并运行 `ollama pull qwen2.5:3b`。只做检索或召回评测时不需要 Ollama。

## 阅读理解：换种说法提问

例如原文写“定制商品不适用七日无理由退货”，问题可以是“按我的要求专门制作的东西，收到三天能因为不喜欢就退掉吗？”

1. 选择“中文语义理解”，勾选“加入阅读理解示例资料”，建立索引。
2. 输入问题，直接检索即可查看相关段落。
3. 需要解释时，启动 Ollama 并勾选“解读资料并回答”。网页展示答案、解读依据和原文引用。
4. 在“召回率评测”选择“阅读理解与同义改写”，测试同义问题能否找到正确证据。

解读使用低温度 JSON 输出，要求保留否定、条件、例外并在依据不足时返回 `insufficient`。程序校验来源编号和引文是否真实存在，格式或引文不合法时不展示生成答案。这只能验证引文存在，不能证明模型推论正确；复杂推理与冲突资料仍需人工核对。

详见 `阅读理解功能说明.md`，包含示例、启动方法、已验证范围与实测对比。

## 创建测试问题与参考原文

下载网页里的示例，或者参考 `examples/evaluation.json`：

```json
{
  "version": 1,
  "questions": [
    {
      "id": "q01",
      "question": "Python 字典的键有什么要求？",
      "answerable": true,
      "relevant": [
        {
          "id": "key-requirements",
          "file": "python_notes.md",
          "page": null,
          "quote": "字典中的键必须是唯一的，并且必须是可哈希的对象。"
        }
      ]
    },
    {
      "id": "q02",
      "question": "牛顿是哪年出生的？",
      "answerable": false,
      "relevant": []
    }
  ]
}
```

- `file` 必须与上传文件名完全一致；同名文件会被拒绝，避免来源歧义。
- PDF `page` 从 1 开始。省略或设为 `null` 表示不限定页码；PDF 建议明确页码。
- `quote` 是来自文档提取文本的原文证据，不是参考答案或关键词。匹配时合并连续空白，其余字符必须一致。
- 每道题的每条证据代表一个需要召回的独立事实。多来源题可写多条；同一事实的重复表述不要标成多个独立事实。不要用整段答案或整页内容作为证据。
- 题目 ID 在题集中唯一，证据 ID 在单题内唯一；完全重复的证据会报错。
- 无答案题必须明确写 `answerable: false` 和空的 `relevant`。

示例共 10 道题（8 道可回答、2 道无答案），只用于功能演示。正式作品建议人工标注至少 30 道，包含同义改写、多来源、易混淆问题，并拆分开发集与最终测试集。

## 指标怎样计算

本项目采用**证据级 Recall@k**：

`单题 Recall@k = 前 k 个片段覆盖的不同证据数 / 该题全部标注证据数`

先计算每道可回答题的召回率，再取算术平均（宏平均）。一个片段可以覆盖多条证据；多个重叠片段命中同一证据只计一次。结果不足 k 条时按实际结果计算，证据分母不变。

例如某题有 A、B 两条证据，检索顺序为“无关、A、重复 A、B”：

| k | Recall@k | Hit@k | RR@k |
|---|---|---|---|
| 1 | 0 | 0 | 0 |
| 2 | 0.5 | 1 | 0.5 |
| 3 | 0.5 | 1 | 0.5 |
| 4 | 1 | 1 | 0.5 |

`Hit Rate@k` 是至少命中一条证据的题目比例。`MRR@k` 是首个相关片段排名倒数的平均，前 k 条无相关片段记 0。全部题目都无答案时，这三项为 `null`（未定义），网页显示提示。

无答案题展示检索结果但不进入上述三个指标的分母。目前检索器总会返回 Top-k，未实现拒答阈值；不能将无答案题结果称为拒答准确率。

## 分块对比实验

批量运行真实语义检索（首次需下载向量模型）：

```bash
python evaluate.py --backend semantic --chunk-sizes 100 200 500 --overlap 40 --ks 1 3 5
```

无需下载模型的离线演示：

```bash
python evaluate.py --backend lexical --chunk-sizes 80 140 240 --overlap 20 --ks 1 3 5
```

评测自己的资料：

```bash
python evaluate.py --documents ./my_documents --dataset ./my_questions.json --backend semantic --chunk-sizes 300 500 800 --overlap 80 --ks 1 3 5 --output ./reports/my_experiment
```

文档目录只读取第一层 PDF、TXT、MD。每种分块配置生成 JSON 完整报告和 CSV 逐题报告，`comparison.json` 汇总对比。重复运行同一输出目录会覆盖同名报告；需要保留实验记录时指定不同 `--output`。

报告包括检索方式、模型名、分块参数、片段数量、文档内容指纹、题集内容指纹、UTC 时间、逐题排序、命中与漏掉的证据。网页也可下载 JSON / CSV。更换网页中的题集、k 或索引设置后，旧报告会隐藏以避免错配。

## 解释漏召回

网页可按 k 查看未完全召回的题目，对照原文和候选片段：

1. 正确证据存在于分块，但未排入前 k：检查同义表达、Embedding 模型、噪声片段以及 k 的选择。
2. 当前所有分块都无法包含标注原文：报告标记 `unmatchable_evidence`。检查文件名、页码、标注错误、PDF 提取差异或分块边界；该证据仍计入分母。
3. 证据横跨边界：使用短而完整的原文证据，或增加重叠。当前按完整引文匹配，不将多个片段拼接后的联合覆盖算作命中。

完整原文匹配便于解释和重复验证，但不自动识别同义证据，漏标的有效来源也不会被计分。因此分数是针对人工标注证据的检索指标，不是全部相关片段的穷尽召回率，更不是生成回答准确率。

增加 k 或增大分块可能提高召回，同时引入更多无关上下文。应结合漏召回案例、上下文长度与响应耗时判断参数，不能只追求单项分数。

## 验证

核心测试只需要 NumPy 和 Python 自带的 unittest，不下载模型：

```bash
python -m unittest discover -s tests -v
```

覆盖手算指标、重叠去重、宏平均、来源和页码约束、无答案题、无效标注、证据跨边界、空检索、k 超过片段数、稳定排序，以及真实离线检索到报告的完整流程。

## 项目结构

```text
app.py                   Streamlit 上传、问答与评测界面
rag.py                   解析、分块、向量化、共享检索和 Ollama 调用
evaluation.py            标注校验、证据匹配、指标和报告导出
evaluate.py              批量分块 / Top-k 实验入口
examples/documents/      自编公开示例资料
examples/evaluation.json 示例标注题集
tests/test_evaluation.py 核心与集成测试
```

当前不支持扫描 PDF 的 OCR，也未持久化索引；报告包含原文片段，公开分享前请检查资料内容。
